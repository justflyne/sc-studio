# Как работает POST /v1/script

## Цепочка загрузки

```mermaid
sequenceDiagram
    participant APK
    participant Boot as libback.so / bootstrap
    participant Server as script.backtobs.xyz:8787
    APK->>Boot: System.loadLibrary("back")
    Boot->>Boot: Новая временная пара X25519 и cnonce
    Boot->>Server: POST /v1/script, have, have_epoch
    Server-->>Boot: protocol, seal_nonce, seal_box
    Boot->>Boot: crypto_box.open; проверки cnonce, подписи и epoch
    alt not_modified=true
        Boot->>Boot: Подтверждение версии локального кэша
    else Полная загрузка
        Boot->>Boot: Проверка SHA-256 source и запись кэша
    end
    Boot->>Boot: Запуск проверенного агента
```

Схема подтверждена исходниками bootstrap; APK на устройстве не запускался.
Выполнены три POST: точное повторение предоставленного запроса, полная загрузка
со своей временной парой и проверка кэша со своей временной парой. Последние два
ответа расшифрованы и проверены.

## Запрос

| Поле | Формат | Назначение по коду |
| --- | --- | --- |
| protocol | число 3 | Версия протокола; независима от v1 в пути |
| client | btb-v59-gadget | Идентификатор семейства загрузчика |
| platform | linux | Process.platform Frida; Android обозначается как Linux |
| arch | arm64 | Архитектура процесса по Process.arch |
| cnonce | 16 случайных байт в hex | Сервер возвращает его внутри защищённого ответа |
| eph_pub | 32 байта в hex | Открытый ключ временной пары X25519 клиента |
| have | строка версии или null | Версия проверенного скрипта из кэша, без кэша null |
| have_epoch | число | Epoch локального кэша, без кэша 0 |

JSON в предоставленном перехвате занимает ровно **236 байт**. have — первые
16 символов SHA-256 скрипта. При исследовании версия ad602661a16ad0b8 и epoch 5
оставались актуальны. Наш первый полный запрос использовал пустую строку have;
сервер её принял. Сам bootstrap без кэша посылает null; fetch_script.py по
умолчанию воспроизводит этот вариант.

Bootstrap формирует HTTP/1.0 и Connection: close. Production-конфигурация
использует порт 8787 и tls=false: защита ответа реализована поверх HTTP.

## Ответ и криптография

Внешний JSON содержит protocol, seal_nonce и seal_box. nonce кодируется Base64
и занимает **24 байта** после декодирования. seal_box — аутентифицированный
шифротекст, также в Base64.

Код прямо вызывает:

```js
nacl.box.open(boxed, nonce, fromHex(RemoteConfig.channelPubKeyHex), ephPriv)
```

Алгоритмы: **X25519 + XSalsa20 + Poly1305**. Подтверждено кодом и успешным
расшифрованием через PyNaCl. Название seal_box не означает crypto_box_seal.
Размер nonce сам по себе не определял алгоритм: первоначальное предположение
о XChaCha20 не подтвердилось.
[Первичная документация crypto_box](https://doc.libsodium.org/public-key_cryptography/authenticated_encryption).

Открытый ключ канала находится в RemoteConfig.channelPubKeyHex. Отдельный
Ed25519-ключ проверки релизов — в RemoteConfig.pubKeyHex. Закрытые ключи сервера
для обычной загрузки своего ответа не требуются и в APK не находятся.

Предоставленный исходный шифротекст не расшифрован: соответствующий eph_priv
исходного клиента неизвестен. Мы создали новые пары и открыли ответы на свои
запросы. Одних eph_pub и Base64 для расшифрования старого перехвата недостаточно.

## Поля открытого JSON

| Поле | Назначение |
| --- | --- |
| protocol | Строго 3 |
| version | Первые 16 символов content_hash |
| epoch | Поколение релиза, участвует в защите от отката |
| content_hash | SHA-256 UTF-8 байтов source |
| rel_sig | Ed25519-подпись релиза, Base64 |
| issued_at | Время выдачи, Unix-секунды |
| cnonce | Эхо nonce именно этого запроса |
| max_age | Предел актуальности кэша; сейчас 86400 секунд |
| not_modified | true — использовать кэш; false — выдан полный source |
| source | Полный JavaScript, отсутствует в ветке not_modified |

Подписываемое сообщение без завершающего перевода строки:

```text
btb-rel-v2\n<version>\n<epoch>\n<content_hash>
```

Проверены Poly1305, совпадение cnonce, Ed25519, epoch и SHA-256 source. Большой
сдвиг issued_at относительно часов клиента bootstrap логирует, но сам по себе
не запрещает запуск.

## Причина короткого ответа в перехвате

| Проверенная ветка | Внешний JSON | seal_box | Открытый JSON | source |
| --- | ---: | ---: | ---: | ---: |
| not_modified=true | 552 байта | 355 байт | 339 байт | отсутствует |
| not_modified=false | 97836 байт | 73318 байт | 73302 байта | 70619 байт |

Ветку not_modified воспроизвели с теми же have и have_epoch, что в перехвате,
и получили те же длины. Поэтому предоставленный короткий ответ соответствует
подтверждению актуального кэша; это вывод из повторного обмена, не расшифрование
первоначального пакета.

Повтор исходного запроса дал 200 и 552 байта с новым nonce/шифротекстом. Это
не доказывает возможность подделки ответа: клиент проверяет свою пару и cnonce.

## Кэш и запуск

Android-пути для com.stealdev.btb:

```text
/data/data/com.stealdev.btb/cache/btb/agent.enc
/data/data/com.stealdev.btb/cache/btb/agent.meta.json
/data/data/com.stealdev.btb/files/btb/epoch.hw
```

agent.enc обфусцирован RC4-drop3072. Ключ вычисляется как
HMAC-SHA256(masterKey, UTF8("enc:" + localNonce)); masterKey встроен в APK и
служит только локальному кэшу, сетевой crypto_box использует другие ключи.
Метаданные хранят версию, epoch, хеш, подпись, localNonce и время подтверждения.
epoch.hw сохраняет максимальный принятый epoch отдельно от очищаемого кэша.
Эти файлы не входят в распакованный APK и с устройства не выгружались.

Актуальный проверенный кэш запускается сразу, затем сервер проверяется в фоне.
Фоновое обновление сохраняется для следующего запуска, без повторного запуска
агента в текущей сессии. Без кэша bootstrap сначала скачивает релиз. Максимальный
срок использования кэша — 24 часа. Агент устанавливает hooks игровой библиотеки.

## Адреса и запросы из кода

| Адрес | Способ | Назначение / степень подтверждения |
| --- | --- | --- |
| script.backtobs.xyz:8787/v1/script | POST JSON | Загрузка/проверка версии; выполнено и проверено |
| script.backtobs.xyz:8787/log?m=... | GET | Отправка журнала, URL-encoded; найдено в коде, нами не вызывалось |
| game.backtobs.xyz:9339 | Native hooks игрового соединения | Игровой сервер, отдельный от HTTP-загрузчика; соединение не выполнялось |
| https://inbox.backtobs.xyz/prices.json | GET в JSON helper | Цены; опционально region и currency |
| https://inbox.backtobs.xyz/log?m=... | GET в helper | Журнал компонента магазина |
| https://inbox.backtobs.xyz/ | WebView | Новости/inbox, bridge к функциям приложения |
| https://store.backtobs.xyz/?section=...&id=... | Открытие веб-магазина | Перенаправление покупки с разделом и ID товара |
| https://cnn.backtobs.xyz, wss://cnn.backtobs.xyz/ws | Таблица замен URL | SDK account/event/rewards/social/presence/inventory/security/guest/CDN; применение реальным трафиком не подтверждено |

Методы и тела SDK-запросов к cnn по таблице URL не восстановлены. Другие сервисы
не запрашивались: цель сетевой части исследования — загрузчик на порту 8787.

Особенность текущего агента: Android-ветка getJSONSocket поддерживает только
http://, но pricesUrl настроен на https://. По этому коду обновление цен
завершается ошибкой до соединения, и остаются fallback-цены. На iOS используется
NSURLSession. Это статический вывод, не тест на устройстве.

## Упаковка bootstrap в libback.so

Конфигурация включает interaction.type="script", path="<embedded>".
Bootstrap и конфигурация разбиты на переставленные фрагменты и обфусцированы
RC4-drop3072 с ключом SHA-256 от встроенного 16-байтного значения. Это отдельный
слой, независимый от сетевого конверта и HMAC локального кэша. extract_client.py
собирает фрагменты через таблицы ELF, снимает упаковку и выделяет 28 модулей;
адреса относятся только к libback.so с записанным SHA-256. Извлечённый код не
выполняется.
