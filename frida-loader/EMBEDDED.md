# Скрипт для встраивания в твою кастомную Frida

Основной файл — **embedded-loader.js**. Это один обычный JavaScript-файл,
без import, без Frida bundle-заголовка и без внешних зависимостей. TweetNaCl,
SHA-256 и кодировки включены в него. Скрипт сам запускает запрос при загрузке,
получает source, проверяет его и исполняет. Если Gadget затем вызывает init(),
он получает ту же Promise: второй запрос и повторный запуск не происходят.

## Сборка после правок

Меняй host, port, ключи и execute в loader.js, затем запускай:

```sh
python3 frida-loader/build_embedded.py
```

Результат:

- embedded-loader.js — готовый JS для твоего существующего механизма встраивания;
- embedded-script.h — тот же JS как массив UTF-8 байт с завершающим NUL;
- embedded-info.json — размер и SHA-256 payload.

Эта команда готовит содержимое для компиляции внутрь твоей библиотеки. Сборка
самой custom Frida выполняется твоей существующей командой сборки.
Сборщику нужны только Python 3, loader.js и каталог embedded-deps: дамп сервера,
Node.js и npm для этой команды не требуются.

## Если в исходниках скрипт хранится как C/C++ массив

Подключи сгенерированный header в тот модуль, который передаёт JS в Gum:

```c
#include "embedded-script.h"

const char *source = btb_get_embedded_script();
size_t source_length = btb_embedded_script_length;
```

Передай source в существующее место создания скрипта. Если твой сборщик сам
читает .js и превращает его в массив/строку, используй embedded-loader.js
в качестве его входного файла — дополнительный header тогда не нужен.

Для правильного ожидания асинхронной загрузки host Gadget должен ожидать Promise
из rpc.exports.init до продолжения приложения. Скрипт начинает работу и сам;
точное место подключения к native-коду определяется исходниками твоей custom
Frida. Путь к ним пока не предоставлен, поэтому её build-system не изменялся.

## Ограничения этого payload

Готовый plain-JS вариант предназначен для Android-агента, который скачан в этом
проекте: он использует native Frida APIs и не обращается к Java bridge. При
наличии Java/ObjC globals в твоём runtime они передаются агенту. Этот вариант
не включает дополнительные Java/ObjC мосты для других агентов/платформ.

Для проверки без исполнения поставь execute: false в loader.js и пересобери.
Для обычного запуска оставь true. Конфиг JSON и отдельный JS-файл внутри APK
для вшитого варианта не требуются.

Ранее подготовленный unsigned APK с официальным Gadget и внешними файлами
относился к другой схеме. Для твоей сборки используй embedded-loader.js или
embedded-script.h и результат компиляции своей библиотеки.

## Проверка

Самозапускающийся JS проверен в Frida 17.23.3, QJS, на Linux в отдельном
процессе. Подписанный безвредный агент загружается и инициализируется один раз;
повторные вызовы init() не повторяют запрос. Повреждённые crypto_box, cnonce,
хеш и подпись отклоняются до исполнения. Проверена передача UTF-8 текста.

С настоящего сервера загружена и проверена версия ad602661a16ad0b8, epoch 5,
70619 байт, с execute=false. Игровой агент на Android здесь не исполнялся.
Header скомпилирован как C99; восстановленные байты точно совпадают с JS,
завершающий NUL присутствует. Результаты — в embedded-verification.json.
